# Читалка: перевод Ветхого Завета по правилам evidence-first

Пользователь читает Библию в переводе, где слово переводится, только если в этом месте у него нет разумной альтернативы. Главы готовит Claude, пользователь читает, задаёт вопросы и поправляет. Порядок: ВЗ → НЗ → Енох, Юбилеи и др. Общение и интерфейс — на русском.

Перед любой работой с переводом прочитай [ПРАВИЛА.md](ПРАВИЛА.md) (утверждённые правила, единственный источник истины) и [DATA.md](DATA.md) (форматы файлов). Для спорных утверждений и трактовок применяй скилл evidence-first.

## Команды

```bash
python tools/fetch_sources.py    # исходники зафиксированных версий + паспорта (уже скачаны)
python tools/build_corpus.py     # собрать corpus/ (не хранится в git)
python tools/check.py            # проверить всё; python tools/check.py Gen 1 — одна глава
python -m unittest discover -s tests
python app/server.py             # читалка на http://127.0.0.1:8795 (у пользователя — «Открыть читалку.vbs» в папке Bible)
python tools/audit_synodal.py    # проверка сопоставления с Синодальным по именам
```

Только стандартная библиотека Python 3, без pip.

## Как готовить главу

0. Прочитай `user/decisions.json` и `user/notes.json`: решения пользователя главнее твоих. Записи с `seenByClaude: false` обсуди с пользователем (применить везде или только в этом месте, правила, раздел 9) и после этого отметь `true`.
1. Собери список словарных слов главы (`corpus/ot/<Книга>/<ггг>.json`, поле `segs[].lemma`). Для каждого слова без файла в `decisions/lexicon/` создай решение: значения с местами-свидетельствами из `corpus/occurrences.json`. Статьи BDB, Strong и STEPBible в `corpus/lexemes.json` — подсказки, а не доказательство: их глоссы бывают богословскими («LORD», «Almighty»).
2. Для каждого слова в каждом месте примени проверку из раздела 1 правил: сколько засвидетельствованных значений подходят здесь по грамматике и контексту. Одно — переводи словом из словаря решений. Больше одного или ни одного — оставляй `display` латиницей и запиши разбор в `places`.
3. Перевод пиши фрагментами (`spans`), как в DATA.md. Вставки ради русской грамматики — `k: "ins"`.
4. Трактовки вноси только с проверенным источником: книга и страница, видео и минута. Книги Бильино запрашивай у пользователя по названию, когда они нужны. Ничего не приписывай автору по пересказам. Традиционная трактовка оформляется так же и оценивается по той же шкале.
5. Запусти `python tools/check.py <Книга> <глава>` и исправь всё до нуля ошибок. Только после этого ставь главе статус `ready`.
6. Решение со статусом `approved` (подтверждено пользователем) не меняй молча. Если новые данные требуют пересмотра, перечисли затронутые главы и спроси.
7. Если нужное правило отсутствует или неясно, не придумывай его в главе: предложи пользователю поправку к ПРАВИЛА.md (версия повышается, затронутые главы перепроверяются).

## Открытые вопросы к правилам (решить, когда встретятся)

- **Кетив / кере** (написанное и то, что масореты велят читать; впервые в Быт 8:17): что идёт в основной текст. В корпусе хранятся оба.
- **Синодальный без заголовков некоторых псалмов** (и Песнь 1:1): в источнике getBible часть заголовков потеряна. Если заголовки понадобятся для сравнения, нужен другой источник Синодального.
- **7 словарных слов без различения омонимов** (`build-report.json`, `lexemesWithoutIndexEntry`, всего 20 употреблений): решать по месту.
- Механическая транслитерация не различает камец и камец хатуф (כָּל даётся как *kāl*). Это только карточка; латинская форма в тексте задаётся вручную в `display`.
